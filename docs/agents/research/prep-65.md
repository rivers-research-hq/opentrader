## 1. Summary

The OpenTrader arena has a **live-updating dashboard** that visualizes two core fields:

- **Battle ring** — per-round discrimination scores, win/loss tally, moving average of edge  
- **Portfolio war** — P&L curves per expert, head-to-head rankings, regime-by-regime P&L  

It lives in **`arena/arena_view.html`** — a standalone HTML/JS page that polls `data/arena/arena_state.json` every 3 seconds. The dashboard runs on a separate HTTP server (port 8098) and is **not** the main harness dashboard (port 8097).

## 2. What's Visualized Per Field

### 2.1 Battle Ring

| Element | Visual |
|---|---|
| **Standings table** | Per-bot `takes`, `take_mean`, `arena_score`, `vs agent` (W/L) |
| **Round history** | Two lines on a canvas: gold line (agent's score per round), blue line (average of all field bots per round) |
| **Gate status** | PASS/FAIL badge with per-window margins |

**Data model** (`arena_state.json.battle`):

```json
{
 "standings": {
 "bot1": { "takes": 42, "take_mean": 0.023, "arena_score": 0.421, "wins": 12, "losses": 5 },
 "agent": { "takes": 156, "take_mean": 0.087, "arena_score": 1.243 },
 ...
 },
 "rounds": [
 { "agent": { "score": 0.12 }, "field": { "bot1": { "score": 0.03 }, ... } },
 ...
 ],
 "h2h": { "bot1": { "wins": 12, "losses": 5 }, ... }
}
```

**How it's built** (`arena/loop.py` → `train_mod.run_iteration`): 
- Each battle round records `agent.score` and `field[bot].score`  
- Scores are derived from per-trade P&L relative to baselines  
- Rounds are appended to `battle.rounds` in the state snapshot

---

### 2.2 Portfolio War

| Element | Visual |
|---|---|
| **Books table** | Per-expert `net_return`, `trades`, `win_rate`, `max_dd` |
| **Equity curve** | Multi-line canvas: each expert's cumulative P&L over time |
| **Regime breakdown** | Separate P&L per regime (up/down) in `war_regime` |

**Data model** (`arena_state.json.war`):

```json
{
 "agent": { "net_return": 12.4, "n_trades": 87, "win_rate": 0.61, "max_dd": -8.3, "equity": [0, 2, 5, 9, ...] },
 "ahl": { ... },
 "citadel": { ... }
}
```

**How it's built:** 
- War runs replay the full 5y archive with each expert  
- `war.equity` is a cumulative array of P&L  
- `war_regime` splits the same data by regime (up/down)

---

### 2.3 Tech Tree (Side Panel)

Shows discovered skills from the curriculum. Each node is a skill; green lines = discovered, gray = locked. Displays `discovered · iteration N` for each lit node.

## 4. How It Stays Cheap During Heavy Training

### 4.1 Polling Budget

- **Poll interval:** 3 seconds (`POLL_MS = 3000`)
- **No WebSocket push** — avoids per-connection overhead during GPU-heavy training
- **Single HTTP server** — lightweight Python `http.server`

### 4.2 Data Sampling

- **State is snapshot-based** — no streaming updates during war/battle runs
- **Arena state is written once per iteration** — after `train_mod.run_iteration` completes
- **Polling reads entire JSON** — ~20KB, negligible I/O

### 4.3 Canvas Rendering

- **Off-screen scaling** — canvases double resolution for retina clarity (context scale factor 2)
- **No animation loops** — static redraw on each poll
- **Simple line series** — no complex physics, just `ctx.lineTo()`

### 4.4 Alternative Tech Considerations (Evaluated)

| Approach | Why not |
|---|---|
| WebSocket push | Overkill; 3s polling is cheap enough; adds complexity |
| TUI (terminal) | Already have `tui_dashboard.py` for quick checks; arena needs multi-panel layout |
| Embedded in harness | Arena state is generated by a different pipeline; separation of concerns |
| Standalone plot (matplotlib) | Need multi-panel, persistent, real-time — web is better |

**Verdict:** The current pattern (HTTP + vanilla JS polling + canvas) is the cheapest and simplest.

## 5. Recommendation: What to Build for #61

### 5.1 Recommended Architecture

**Live-updating dashboard page** (port 8098) — expand `arena_view.html` into a single page with:

1. **Left panel:** Battle ring (standings + round history + gate)  
2. **Right panel:** Portfolio war (books + equity curves + regime split)  
3. **Bottom:** Tech tree (discovered skills)  

This is essentially the existing layout but with:
- A unified "live" feel (polling every 3s)
- Better visual separation of the two fields
- A "refresh" button to force a re-poll
- A "show legend" toggle for the canvas lines

### 5.2 Per Field — What to Visualize

| Field | Must-have | Nice-to-have |
|---|---|---|
| **Battle ring** | Standings table, round history (two lines), gate badge | Per-bot breakdown on hover, regime-weighted scores |
| **Portfolio war** | Equity curves (multi-line), books table, regime split | Per-trade markers, cumulative vs. periodic P&L, max drawdown annotations |
| **Tech tree** | Discovery timeline, iteration count, tier grouping | Progress bars toward mastery, prerequisites highlighted |

### 5.3 How It Stays Cheap

- **Sampling:** Only poll every 3s — during heavy training this is <1% of CPU
- **Canvas:** Redraw from JSON on each poll — no per-frame animation
- **Single-threaded:** No async event loop for polling; vanilla `setTimeout`
- **Data size:** Arena state is ~20KB; JSON parsing is trivial

### 5.4 Implementation Notes

- **Reuse existing code:** `arena/arena_view.html` already has all the rendering logic
- **Add a "Live" badge** in the header
- **Add a "Run Status" banner** from `run_status.json`
- **Export to GIF:** Use the existing GIF generation pipeline to create a periodic snapshot for PRs (see `showcase/*.gif`)
